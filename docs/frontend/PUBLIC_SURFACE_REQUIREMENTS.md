> Scope: define what the public dCorps surface must contain in the current phase so the product can be shared proudly without overstating maturity.

---

## 1. Canonical rule

The canonical public surface is the official app.

Public docs complement the app. Static website surfaces are optional and transitional.

---

## 2. What the current phase must show

For the current phase, the public surface must show:

- a live registry or explorer landing surface;
- explorer-like search and discovery by entity, wallet, or record;
- what the narrow live workflow is;
- what phase the project is in right now;
- what exists today versus what is planned later;
- how serious users or design partners can engage;
- where integrated reference material lives inside the app.

This is more important than having many pages.

---

## 3. Required public capabilities

The current-phase public surface should include equivalents for:

- a registry landing route;
- an entity detail route;
- explorer-style search and filtering;
- a workspace route;
- governance and treasury entry routes;
- an integrated reference route set (`about`, `whitepaper`, `security`, `roadmap`);
- a roadmap or phase-status route;
- a risk and legal route;
- a testnet or partner-access route.

These may live inside one app shell if the experience remains clear.

---

## 4. Truthfulness requirements

The public surface must:

- identify the current phase explicitly;
- avoid implying production readiness where only proof of concept exists;
- label planned features as planned;
- avoid public token-sale or investor messaging before the project has earned it.

---

## 5. Design requirements

The surface should feel:

- serious;
- product-led;
- concise;
- technically credible;
- visually intentional.

It should avoid:

- brochure-first design;
- crypto landing-page cliches;
- inflated ecosystem language;
- placeholder-like product UI.

The preferred visual language is:

- black background;
- white-first typography;
- thin grid and panel lines;
- high-density but calm interface structure;
- strong table, rail, and inspector patterns.

---

## 6. Current recommendation

The next frontend milestone is to make `dcorps-app` the single proud public surface for:

- the public registry and explorer;
- the narrow workflow;
- the testnet posture; and
- access paths for design partners.
