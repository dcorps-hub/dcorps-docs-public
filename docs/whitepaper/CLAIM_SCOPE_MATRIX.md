# Whitepaper Claim Scope Matrix

**Document type**: Whitepaper claim reconciliation
**Doc ID**: WHITEPAPER-CLAIM-SCOPE-MATRIX
**Status**: Draft v0.1
**Last updated**: 2026-05-15

> Scope: maps the whitepaper suite's major product, protocol, token, governance, and ecosystem claims to the intended delivery stage. If an older whitepaper paragraph sounds broader than this matrix, this matrix is the safer interpretation until the narrower claim is implemented, reviewed, and published in current docs.

---

## Stage Labels

- **Mainnet beta**: may ship in the smallest credible public product if implementation, review, operations, and legal gates pass.
- **Genesis/TGE**: gated on the public DCHUB distribution path, steward/foundation readiness, token controls, and launch disclosures.
- **Post-launch**: useful after the mainnet beta proves the narrow workflow; not required for the first public version.
- **Ecosystem**: optional or partner-led expansion that should not be presented as committed launch scope.

---

## Current Boundary

- dCorps is in development. Mainnet is not live.
- Public DCHUB Genesis/TGE has not happened.
- Token-governed protocol authority is not active.
- The foundation or equivalent steward path is not executed.
- The first product target remains a narrow app-first workflow for entity creation, roles, wallets, records, identity, activity, and honest read models.

## Use Rule

Before publishing or presenting a whitepaper claim, check:

1. The claim appears in this matrix or is narrower than an existing row.
2. The current roadmap phase supports the stage.
3. The app, protocol, indexer, operations, legal, and security evidence support the claim.
4. If the claim concerns public tokens, foundation/stewardship, liquidity, legal posture, public launch, or investor material, it receives explicit human review before publication.
